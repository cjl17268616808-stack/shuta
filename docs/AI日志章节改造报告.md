## 三、改动二：🔑 学习记录（现场生成）

在 SP-1 末尾新增一个「我的学习记录」面板 —— **它不写死任何数据，由浏览器读取真实进度现场渲染**。

### 规则

> **只把已经通关的知识点写进日志；没学完的整章都不出现。**

### 实现

```js
// comicEngine.renderLiveProgress(panel)
chapters.forEach((ch) => {
    grandTotal += ch.knowledgePoints.length;
    const done = ch.knowledgePoints.filter(k => this.completedKps.includes(k.id));
    doneTotal += done.length;
    if (done.length === 0) return;   // ← 没学完的整章不出现
    // …
});
```

数据源直接读 `comicEngine.completedKps`——和左上角进度徽章是**同一个来源**，
所以它永远等于真实进度，不可能对不上。

## 五、⚠️ 途中踩到的一个契约问题

新增面板后，全量通关测试报错：

```
SP-1 分镜5 [click] 没有继续按钮
```

**根因**：引擎对 `click` 型互动的契约是「继续按钮必须渲染在
`#interaction-area` 内」，而我的新面板把按钮放在了 `#panel-controls`。

**修法**：改**引擎**让它遵守自己的契约（把 `id="interaction-area"` 放到面板主体、
按钮放进其中的 `.lp-actions` 行），**而不是去改测试**。
测试能通过是因为界面真的对了，不是因为把断言放宽了。

## 八、🔴 顺带修掉一个误导性很强的配色 bug

用户在判断练习里发现：**对一句错误的话正确地点了「不对」，卡片却变成红色**——看起来像答错了。

**根因**（`comicEngine.js` 原第 3410 行）：

```js
card.classList.add('locked', st.answer ? 'is-true' : 'is-false');
//                              ^^^^^^^^^ 按【句子本身对不对】上色
```

`is-false` 被红色样式（`#d63031` / `#ffe3e3`）绑定，于是「答对」反而显示成错误色。
这个类同时承担了两个职责：**卡片配色** 和 **哪个按钮保持高亮**。

**修法**：把两个职责拆开

| 类名 | 含义 | 配色 |
|---|---|---|
| `is-correct` | **你答对了**（唯一的判定色） | 🟢 绿色 |
| `picked-yes` / `picked-no` | 你点的是哪个按钮 | 仅控制按钮高亮 |

句子本身的真假改由文字说明，并在后面补一句 **「—— 你判对了」**，
避免 ✓/✗ 记号和绿色卡片互相打架：

```
✗ 这句是错的 —— 你判对了
AI 不署名知识：文字里的事实、数字、结论都要对照官方文档逐条核过……
```

**实测**：三类说法（真/假/假）全部按正确答案作答后，**三张卡片统一为绿色**，
按钮高亮分别落在「对」「不对」「不对」上；答错仍走抖动提示，不变色。
