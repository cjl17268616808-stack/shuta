## 二、发现的问题与修复

### 🔴 问题 1（严重）：纯讲解页无"继续"按钮，学生被卡死

**现象**
共 **11 个分镜**在学完后没有任何可推进的按钮，学生只能刷新页面。

**受影响分镜清单**

| 知识点 | 分镜 | 场景名 | 丢失的按钮文案 |
|---|---|---|---|
| 1-1 初识数据库 | p5 | db-vs-dbms | 懂了，做题 ▶ |
| 1-2 表、行、列 | p2 | table-anatomy | — |
| 1-2 表、行、列 | p4 | index-miss | — |
| 1-3 主键与外键 | p4 | pk-pick | — |
| 1-4 SQL 语言初探 | p4 | sql-declare | — |
| 1-5 增删改查（CRUD） | p4 | crud-sql | — |
| 2-1 数据完整性约束 | p5 | constraint-check | — |
| 2-2 索引：为什么查得快 | p4 | index-speed | — |
| 2-3 事务：要么全成功，要么全失败 | p5 | tx-states | — |
| 2-4 视图与存储过程 | p5 | view-def | — |
| 2-5 SQL 注入与防范 | p5 | sql-injection | — |

**根因**
\`js/comicEngine.js\` 的 \`renderScenePanel()\` 中：
这 11 个分镜是"纯讲解页"——只有 \`scene\` + \`explain\` + \`nextText\`，没有 \`stage\` 道具，也没有 \`interaction\`。
引擎在找不到可点击道具时**直接 \`return\`**，导致该页配置的 \`nextText\` 从未被渲染。

**修复**
在该分支补一个"继续"按钮，文案优先取数据里的 \`nextText\`，取不到则回退 \`继续 ▶\`。

\`\`\`js
if (clickables.length === 0) {
    const nextBtn = document.createElement('button');
    nextBtn.className = 'comic-btn';
    nextBtn.innerText = panel.nextText || '继续 ▶';
    nextBtn.onclick = () => this.nextPanel();
    interactionArea.appendChild(nextBtn);
    return;
}
\`\`\`

### 🟠 问题 2（中等）：收集页"继续"按钮守卫条件过宽

**现象**
点击归位类分镜（如 1-1/p1 收集 5 个字段）中，若 \`interactionArea\` 里已存在任意 \`.comic-btn\`，收集满后**不会生成继续按钮**。

**根因**
原判断为 \`!interactionArea.querySelector('.comic-btn')\`——只要容器里有**任何**按钮就跳过创建，条件过宽。

**修复**
改用专属类名精确判断，只判断"本页是否已加过继续按钮"：

\`\`\`js
if (collected >= needed && !interactionArea.querySelector('.collect-next-btn')) {
\`\`\`
