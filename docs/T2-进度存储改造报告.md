# 数塔项目 · T2 学习进度存储改造报告

> 目标：把"只存在浏览器缓存里的学习进度"改为**不依赖缓存**，清缓存/换浏览器/隐私模式都不丢。
> 状态：✅ 已完成并通过 5 类场景验证

---

## 一、改造前的问题

\`js/comicEngine.js\` 原实现**只**依赖 \`localStorage\`：

\`\`\`js
initProgress() {
    const saved = localStorage.getItem('shuta_progress');   // ← 缓存清空 = 进度归零
    if (saved) { try { this.completedKps = JSON.parse(saved); } catch(e) { this.completedKps = []; } }
    this.updateProgressUI();
},
saveProgress(kpId) {
    ...
    localStorage.setItem('shuta_progress', JSON.stringify(this.completedKps));  // ← 缓存被禁 = 直接抛错
}
\`\`\`

**三个具体缺陷**
1. 清空缓存 / 换浏览器 / 隐私模式 → 进度**全部归零**。
2. 隐私模式下 \`localStorage\` 读写会**抛异常**，可能中断渲染。
3. 配额写满时 \`setItem\` 抛错，未捕获。

---

## 二、改造思路（三层容错）

静态 HTML 页面**无法把数据写回自己的源文件**（浏览器安全模型限制），
因此"存进 HTML"落地为 **页面内嵌基线 + 运行时增量** 的组合：

| 层 | 载体 | 作用 | 缓存清空后 |
|---|---|---|---|
| ① 内嵌基线 | \`js/progress-baseline.js\`（由 Python 编译生成） | 页面自带的进度基线，与浏览器缓存**完全无关** | ✅ 仍在 |
| ② 增量缓存 | \`localStorage['shuta_progress']\` | 记录本次学习新通关的知识点 | 丢失，但可由①兜底 |
| ③ 内存兜底 | \`comicEngine.completedKps\` | 缓存被禁用时保证功能可用、不报错 | ✅ 不崩溃 |

启动时执行 **基线 ∪ 缓存** 求并集去重，再回写缓存。

## 三、具体改动

### 1. 新增 \`js/progress-baseline.js\`（编译自动生成）

\`\`\`js
window.SHUTA_PROGRESS_BASELINE = {
    "total": 32,
    "completedKps": [],          // 可预置，如 ["1-1","1-2"]
    "note": "内嵌基线进度：与浏览器缓存无关，清缓存不丢失。"
};
\`\`\`

已接入 \`python_src/build_data.py\`，每次编译 content 时**自动重新生成**，\`total\` 与知识点数量永远同步。

### 2. 重写进度读写（\`js/comicEngine.js\`）

- 新增 \`safeStorageGet/Set/Remove\`：所有 \`localStorage\` 访问包在 try/catch 中，异常一律降级，**绝不打断渲染**。
- \`initProgress()\`：读基线 + 读缓存 → **并集去重** → 回写。
- \`persistProgress()\`：统一持久化出口，返回是否成功；失败只影响"下次打开的记忆"，不影响本次使用。
- \`saveProgress()\`：缓存不可用时语音提示"本次会话内有效"，功能照常。
- \`resetProgress()\`：同时清理 \`shuta_progress\`、\`shuta_home_done\`、\`shuta_home_selected\` 三个关联键。
- \`updateProgressUI()\`：总数优先从数据计算，兜底用基线 \`total\`。

### 3. 修正首页写死的总数

[index.html](E:\XM\shuta\index.html) 原写死 \`33\`，实际为 **32** 个知识点 → 已修正为 32，并改为运行时自动计算。

### 4. 课程内补充进度说明

设置面板新增"📊 学习进度说明"文案，明确告知用户：
通关记录已写入课程文件、清缓存不丢、以及如何重置。
