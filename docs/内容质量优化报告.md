## 一、先研究：廖雪峰到底好在哪

我实际抓取了他的教程页面（Python 教程「简介」「数据类型和变量」「面向对象编程」等）逐段分析，提炼出 6 条核心手法：

| # | 手法 | 原文例子 |
|---|---|---|
| 1 | **先建立动机**：不直接给定义，先让你感到「没有它很痛」 | 「C 语言要写 1000 行，Java 100 行，Python 只要 20 行」 |
| 2 | **概念一句话锚定 + 说清与相邻概念的差异** | 「面向过程=命令集合；面向对象=对象集合，对象之间传消息」 |
| 3 | **立刻给可代入的完整例子** | `std1={'name':'Michael','score':98}` → `class Student` → `bart.print_score()` |
| 4 | **解释「为什么这样设计」** | 「面向对象的思想是从自然界来的，Class 是抽象，Instance 是具体」 |
| 5 | **结尾给一句话小结** | 「数据封装、继承和多态是面向对象的三大特点」 |
| 6 | **零起点假设**，不预设前置知识 | 全篇不出现未解释的术语 |

## 三、改造方法

每个 `explain` 统一为廖雪峰式四段结构：

```
🤔 先想一个问题 / 真实事故现场   ← 建立动机（原来最缺的一段）
      ↓
📐 概念一句话锚定 + 与相邻概念的区别
      ↓
🎯 具体例子（带数字、带 <code> 代码、带真实表名字段）
      ↓
🧠 一句话记住 / 小结              ← 原来最缺的第二段
```

**同时严格保留数塔自身的风格**：
- 塔库口吻（「哔——」）、拟声字、表情符号
- `<strong>` 加粗关键术语、`<code>` 包代码
- **全部严谨性加分项一个没删**（这是数塔相对廖雪峰的差异化优势）

### 代表性改写对比

**1-1 第1页「初识数据库」（56 → 355 字）**

改前：「😵 30 个同学的信息写在纸条上到处乱扔，找个人要翻半天！数据一『散』，查找、更新、统计全都成了体力活。」

改后：「😵 30 个同学的学号、姓名、成绩全写在纸条上随便一扔：老师要找『小明的成绩』得翻半天，改一个分数要重抄一遍，统计平均分要数半小时，两个人同时改还会互相覆盖……🎯 量化一下：30 条数据放进表格里 3 秒就能定位；散着放平均要翻 15 张纸条，涨到 3000 条就是 1500 张，工作量直接翻百倍……🧠 一句话记住：**数据不是不能存，而是不能散着存**。」

**6-1 第1页「什么是向量」（237 → 511 字）**

改前：直接给定义——「Embedding（嵌入）：把文本、图片、音频喂给一个编码模型，它会输出一串固定长度的实数向量……」

改后：先给痛点——「如果让你写一条 `WHERE content LIKE '%猫%'`，用户搜『猫咪喂养』就永远搜不到『怎么养猫』——字面不同、意思相同，关键词匹配天生抓不住」，再锚定概念、给 768 维具体数值、以「向量 = 模型替语义画的坐标；模型一换，整张地图都得重画」收束。

## 七、过程中的风险与处置

1. **第 3 章一度被我改出语法错误**（漏了字符串结尾引号，导致 `build_data.py` 全部失败，
   另外两个并行 agent 因此被阻塞）。已定位修复。教训：多 agent 并行改内容时，
   一个文件的语法错误会阻塞所有人的编译。

2. **第 2 章曾被 write 工具截断**（尾部 `reviewQuiz` 内容丢失），该章 agent 用 base64 落盘修复。
   我已验证修复后的文件：25 页、复习题 3 题/节、AST 解析通过。

3. **项目不是 git 仓库**，没有版本回退。本次改动全部有验证脚本兜底，
   但后续建议先 `git init` 或至少打包备份。
