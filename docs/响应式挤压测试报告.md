## 一、测试方法

Chrome headless 的 `--window-size` 有**最小宽度限制**（请求 375 实际只给 512），
直接设窗口大小测不出真机效果。

改用 **iframe 沙盒**：把页面放进指定宽度的 iframe，iframe 的视口就是真实视口，
媒体查询会按该宽度生效。测试宽度：**360 / 414 / 600 / 768 / 1024**。

检测项：`documentElement.scrollWidth > clientWidth`（横向溢出），
并逐元素找出"比视口宽"或"右边超出视口"的罪魁。

## 二、🔴 关键 bug：1024px 以下全部横向溢出

### 现象

| 宽度 | 溢出的页面 |
|---|---|
| 360 | 落地页 / 章节页 / 学习页 / 数塔之家 —— **全部溢出 24px** |
| 414 | 全部溢出 20px |
| 600 | 全部溢出 9px |
| 768 | 全部溢出 2px |
| 1024 | 正常 |

溢出元素清一色是 `#app`、`#stage`、`.chapter-list`、`#hero-banner`。

### 根因

`body` 是 `display:flex`（横向排列），而 **`.comic-bg-decor`（背景装饰层）完全没有定位规则**——
它是个普通的静态 div，于是变成了一个真实的弹性子项，**白占 66px 宽度**，
把 `#app` 向右挤了 53px：

```
body 的直接子元素（实测）：
  div.comic-bg-decor   rect=[-13, 53]  w=66  pos=static   ← 罪魁
  div#app              rect=[53, 373]  w=320
```

宽屏时只是内容偏右、不溢出；**窄屏就顶出边界，右侧内容被直接切掉**。

### 修复

给装饰层补上定位，让它脱离文档流：

```css
.comic-bg-decor {
    position: fixed;
    inset: 0;
    z-index: 0;
    pointer-events: none;
    overflow: hidden;
}
```

### 结果

| 宽度 | 修复前 | 修复后 |
|---|---|---|
| 360 | 溢出 24px | ✅ OK |
| 414 | 溢出 20px | ✅ OK |
| 600 | 溢出 9px | ✅ OK |
| 768 | 溢出 2px | ✅ OK |
| 1024 | OK | ✅ OK |

**4 个页面 × 5 个宽度，全部 `scrollWidth == clientWidth`。**
（`body` 上的 `overflow-x:hidden` 只是把滚动条藏了，内容该切还是切，
所以必须修根因而不是加遮罩。）

## 三、另外修掉的 3 处体验问题

### 1. 顶部按钮在窄屏堆成 4 行

360px 下 6 个按钮 + 进度徽章挤成 4 行，占掉约 150px 首屏高度。

**修法**：给「数塔操作说明」「数塔之家」两个长文案按钮的文字套 `.btn-label`，
窄屏只显示图标（tooltip 保留）：

```css
@media (max-width: 768px) { .btn-label { display: none; } }
```

→ 从 4 行压到 **2 行**。

### 2. 塔库角色遮挡章节卡

`.taku-area` 是 `position:fixed`，机器人原本 120px 宽，
在 360px 屏上几乎占满宽度，浮在章节卡之上。

**修法**：窄屏缩小 + 内容底部留白。

```css
@media (max-width: 768px) {
    .taku-robot { width: 78px; height: 92px; }
    .taku-dialog-box { max-width: 56vw; font-size: 12.5px; }
    #app { padding-bottom: 150px; }   /* 让最后一张卡能滚到塔库上方 */
}
@media (max-width: 500px) { .taku-robot { width: 66px; height: 78px; } }
```

### 3. 讲解气泡在超窄屏挤成一条

`.bubble` 用 `padding-left: 98px` 给绝对定位的头像让位，
360px 上正文只剩两百来像素，一行挤不下几个字。

**修法**：≤480px 时头像移到正上方居中，正文占满整行。

```css
@media (max-width: 480px) {
    .bubble { padding: 56px 14px 16px 14px !important; font-size: 14.5px !important; }
    .bubble-avatar { left: 50% !important; top: 7px !important; transform: translateX(-50%) rotate(-3deg) !important; width: 40px !important; height: 40px !important; }
    .bubble::before, .bubble::after { display: none !important; }
}
```

## 六、过程说明：我犯的一个错误（已修正）

做气泡适配时，我用「读全文 → 拼接 → 写回」的方式改 `css/style.css`。
但读取工具有 **2000 行上限**，而该文件有 2254 行 ——
**写回时把末尾 674 行 CSS 截掉了**，丢失了 `.guide-overlay`、`.rec-flag`、
`.hero-guide-overlay`、`.judge-card` 等规则。

**处置**：从上一次打包的 `数塔20261011.zip` 里取回完好的 `style.css`（2153 行），
覆盖损坏文件，再按顺序重放打包后的两处改动（装饰层修复 + 气泡适配）。
已逐条复核所有关键规则存在、括号平衡、通关测试通过。

**教训**：大文件绝不能用「读全文→写回」，必须用定点替换或独立文件追加。
本报告里最后那处气泡 CSS 就是用 `[System.IO.File]::AppendAllText` 单独追加的。
