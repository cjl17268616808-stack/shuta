# 数塔内容改写指南（对标廖雪峰教程）

## 目标
把数塔的讲解页从「开门见山讲定义」改成廖雪峰式的
**「先讲为什么痛 → 给量化对比 → 给具体例子 → 一句话小结」**。

## 廖雪峰的核心手法（必须学会并模仿）
1. **先建立动机**：不直接给定义，先让读者感到「没有这个概念会很痛」。
   例：「C 语言要写 1000 行，Java 100 行，Python 只要 20 行」
2. **概念用一句话锚定 + 说清与相邻概念的差异**。
   例：「面向过程=命令集合；面向对象=对象集合，对象之间传消息」
3. **立刻给可运行/可代入的完整例子**，不要停在抽象描述。
   例：`std1={'name':'Michael','score':98}` → `class Student` → `bart.print_score()`
4. **解释「为什么这样设计」，而不只说「是什么」**。
   例：「面向对象的思想是从自然界来的，Class 是抽象，Instance 是具体」
5. **结尾给一句话小结/口诀收束**。
6. **零起点假设**，不预设读者懂前置知识。

## 数塔必须保留的风格
- 塔库口吻（「哔——」），拟声字，表情符号
- 漫画分镜感，`<strong>` 加粗关键术语，`<code>` 包代码
- 严谨性（这是数塔的强项，别丢）：版本差异、易错点、面试考点

## 硬性要求
- **只改自己那一章的 .py 文件**，不要碰其他章节、data.js、comicEngine.js
- 保持所有字段结构不变：`id` / `taku` / `scene` / `sfx` / `explain` / `stage` / `interaction` /
  `dropZone` / `collectCount` / `nextText` / `reviewQuiz` 一律原样保留
- **只改写 `explain` 字段的文字**（以及必要时 `taku.dialogue` 的开场引导）
- Python 语法必须合法（字符串里的引号要转义正确）
- 每页 explain 长度控制在 **350~650 字符**（原来太短的要充实，太长要精简）

## 每个 explain 的推荐结构
```
🤔 先想一个问题 / 现象（建立动机，1-2 句）
   ↓
📐 概念定义（一句话锚定）+ 与相邻概念的区别
   ↓
🎯 具体例子（带数字、带 <code> 代码）
   ↓
🧠 一句话记住 / 小结
```
不是每页都要完整四段，但**动机**和**小结**至少要有其一，**具体例子**尽量要有。
