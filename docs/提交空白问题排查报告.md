## 二、根因：沙盒 iframe 里 localStorage 抛异常，启动流程被静默中断

### 复现

我写了一个测试页，**模拟竞赛平台的沙盒 iframe**（让 `localStorage` 访问抛 `SecurityError`），得到：

| 指标 | 复现结果 |
|---|---|
| 章节卡数量 | **0** |
| 塔库文案 | **系统启动中...**（卡死） |
| textbookData | loaded（数据其实是好的） |
| 全局 JS 报错 | **none**（一个都抓不到！） |

**和你的截图逐项吻合。**

### 调用链

\`\`\`
main.js: DOMContentLoaded(async) → takuEngine.init()
   → initDrag()
      → localStorage.getItem('takuLeft')   ← 沙盒里抛 SecurityError
   ← 异常冒泡出 init()
← 异常冒泡出 async 回调
→ 变成【未处理的 Promise rejection】
→ window.onerror 抓不到，控制台只留一行 warning
→ 后面的 renderChapters() 永远不执行
→ 首页空白、塔库停在初始文案
\`\`\`

**关键点**：因为启动回调是 `async`，任何一步抛出都会变成**被静默吞掉的 Promise rejection**。
这就是为什么"没有报错"但"整页空白"——最难查的一类故障。

---

## 三、修复（两层）

### 第 1 层：堵住根因

`js/takuEngine.js` 里有 2 处未保护的 localStorage 访问（另外 2 处和 shutaHome 的 1 处本来就有 try/catch）：

\`\`\`js
// 修复前
const savedLeft = localStorage.getItem('takuLeft');   // ← 沙盒里直接抛
const savedTop  = localStorage.getItem('takuTop');

// 修复后
let savedLeft = null, savedTop = null;
try {
    savedLeft = localStorage.getItem('takuLeft');
    savedTop  = localStorage.getItem('takuTop');
} catch (e) { /* 存储不可用 → 用默认位置 */ }
\`\`\`

拖拽位置的写入同样加了保护。

### 第 2 层：启动容错（更重要）

光堵一个点不够——平台上还可能禁音频、禁语音合成、禁 fetch。
我把 `js/main.js` 的启动流程重写成**每一步独立 try 住**：

\`\`\`js
const safe = (label, fn) => {
    try { return fn(); }
    catch (e) { bootErrors.push(label + ': ' + e.message); return null; }
};

safe('背景音乐初始化', () => bgmEngine.init());
safe('塔库初始化',     () => takuEngine.init());
// ……数据加载、渲染、欢迎语、引导、各种事件绑定，全部 safe() 包住
\`\`\`

并加了两个诊断设施：
- `window.__shutaBootErrors`：启动问题清单，随时可查
- `unhandledrejection` 监听：把以前被吞掉的 Promise 异常**打印到控制台**（以后再出这类问题，一眼可见）
- 渲染失败时显示可见错误提示，而不是留一片空白

**原则：任何非核心环节挂掉，都不能影响"把教材内容渲染出来"。**

## 四、顺带修掉的两个交付问题

### 1. 交付包里混进了 12.7 MB 未压缩原图

我给插画做压缩时把原图备份放在 `assets/img-originals/`，
而打包脚本是按**目录白名单**收集的（`assets` 整个目录），于是原图被整包带走：

| | 修复前 | 修复后 |
|---|---|---|
| 交付包大小 | **22.77 MB** | **8.9 MB** |
| 解压后 | 25.04 MB | 11.16 MB |

处理：原图移到根目录 `原图备份/`（不在打包白名单内），
并在 `tools/pack.ps1` 的排除规则里加上 `img-originals|备份`——以后放回去也不会再被打进包。

同时移除了 1.5 MB 的 `assets/welcome-hero.png`（旧欢迎卡专用，已无任何引用）。

### 2. CSS 有一处损坏

`css/style.css` 里有一段**没有选择器的孤立规则**（`margin: 0; }`），
导致其后所有规则的括号配平被破坏。已修复，现在括号完全平衡。
