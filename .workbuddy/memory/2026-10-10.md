## 反馈改造：互动多样化 + 去游戏化定位

**用户反馈**：① 互动没必要非得是"捡拾掉落的数据"，要有各种花样（判定、质疑、手动输入、用户描述、收集等）；② 数塔不是游戏，是"动画+漫画+插画+互动+文字"一体的质量过关但有趣的教学网站。

### 一、新增 4 种互动模式（js/comicEngine.js + css/style.css）

| type | 中文名 | 玩法 | 关键字段 |
|---|---|---|---|
| judge | ⚖️ 判断练习 | 逐句判对错，判完即看解释，判错可改判 | statements:[{text, answer:bool, why}] ≥2，why 必填 |
| challenge | 🤨 质疑练习 | 塔库一段话藏 1 处错，点可疑片段质疑 | segments 拼成连贯一段，check:true 段 ≥2，**恰好 1 处 wrong:true**（check+why），每个 check 段都要 why |
| input | ⌨️ 动手写答案 | 输入框作答回车提交，错 2 次亮 hint | accept ≥1（归一化比较：忽略大小写/全半角/空格/引号/句尾标点），hint 必填 |
| describe | ✍️ 用自己的话说说 | 写理解→对照参考理解+关键词命中提示，不判对错 | reference 必填，keywords 3~5，minChars 默认 15 |

- 四种模式注册进 NEW_MODES（第 12~15 种模式），走 renderModePanel 双栏布局（左边互动板+右边漫画）
- CSS 类：.judge-* / .claim-*（.claim-seg 可点质疑）/ .input-* / .describe-*，均漫画风（3.5px 描边+硬阴影）
- 新工具 `.workbuddy/verify-content.py`：**本机没有 node**，这是 verify-content.mjs 的 Python 移植（校验 15 种模式 schema+红线+措辞扫描），支持 `python .workbuddy/verify-content.py N`（直接读章节 .py，不用先 build）、`sp`（SP 章只查 schema，旧 mjs 从来没查过 SP）、无参（读 textbook.json 全量+SP）。mjs 版也同步更新了（有 node 的机器用）
